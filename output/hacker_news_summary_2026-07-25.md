## 1. 一项旧专利启发了新型“Y型拉链”，这是一种三面紧固件。

**原文标题**: An old patent inspired the new "Y-zipper", a three-sided fastener

**原文链接**: [https://news.mit.edu/2026/three-sided-y-zipper-design-0504](https://news.mit.edu/2026/three-sided-y-zipper-design-0504)

麻省理工学院（MIT）计算机科学与人工智能实验室（CSAIL）的研究人员开发出了一种名为“Y型拉链”（Y-zipper）的三面紧固件，能够使物体在柔性与刚性状态之间快速切换。该项目的灵感源自MIT教授比尔·弗里曼（Bill Freeman）在1985年获得的一项专利，他最初构想将这种三角形拉链用于家居装饰和服装。

Y型拉链系统利用定制的软件工具，允许用户设计并3D打印出柔性条带，当这些条带拉合在一起时，会形成刚性的三角形管状结构。用户可以通过四种运动“原语”——直线、弯曲、卷曲或扭转——来定制拉链的行为，从而决定刚性结构的最终形状。

**主要应用包括：**
*   **快速组装：** 配备Y型拉链的帐篷仅需80秒即可搭建完成，而手动搭建则需要6分钟。
*   **医疗穿戴设备：** 可调节的手腕固定支具，白天可以调松以保证舒适度，夜间则可以收紧以提供支撑。
*   **机器人与艺术：** 电动化Y型拉链可以制造出能够改变腿部高度以适应地形的机器人，或像花朵一样“绽放”的动态艺术装置。

研究人员使用聚乳酸（PLA）和热塑性聚氨酯（TPU）等塑料测试了紧固件的耐用性，发现它们在损坏前可经受18,000次拉合循环。论文第一作者李佳冀（Jiaji Li）表示，该技术未来可以使用金属等更坚固的材料进行规模化应用，用于灾难救援避难所或太空探索。通过消除柔性与刚性状态之间的界限，Y型拉链为动态组装和具身智能提供了一种可扩展且可逆的方法。

## 2. 硬盘可能已满

**原文标题**: Harddrive Is Probably Full

**原文链接**: [https://www.marginalia.nu/log/a_139_hdd/](https://www.marginalia.nu/log/a_139_hdd/)

本文探讨了一种现象：无论总容量如何，资源（特别是数字存储）往往趋于饱和。作者结合个人经验和民调数据指出，尽管存储空间已从兆字节扩展到数十太字节，但剩余空间的比例始终保持在极低水平。

这种“硬盘满载”问题被视为一种超越技术范畴的普遍人类倾向。它在软件开发中表现为技术债和缺乏优化，在城市规划中表现为道路拥堵，在个人生活中则表现为过度饱和的日程。作者认为，我们通常会忽视这些问题，直到它们达到某个“痛点”——即混乱程度已让人不堪重负，迫使我们不得不进行维持基本运转的最低限度清理。

其中的核心矛盾是“杰文斯悖论”：增加某种资源的供应往往会导致消费增加，而非产生盈余。为了在效率需求与过早优化的陷阱之间达成平衡，作者建议将限制“武器化”。通过施加人为限制——例如设定财务预算，或在树莓派等低性能硬件上测试软件——可以倒逼优化并维持效率。

作者最后总结道，虽然资源的扩展承诺了更强的处理能力，但往往只是让我们以更高、更低效的成本去完成同样的任务。解决方案是刻意在小于总可用资源的限制范围内进行运作。

## 8. 编写一个没有 main() 的（有效）C 程序

**原文标题**: Writing a (valid) C program without main()

**原文链接**: [https://labs.iximiuz.com/tutorials/c-program-without-main-a1eea557](https://labs.iximiuz.com/tutorials/c-program-without-main-a1eea557)

This article demonstrates that while `main()` is the standard entry point for C programs, it is a convention of the C runtime (CRT) rather than a strict requirement of the Linux operating system. The author explores this by walking through the four stages of the C compilation pipeline:

1.  **Preprocessor:** Handles macros and directives (e.g., `#include`).
2.  **Compiler:** Translates C code into architecture-specific assembly.
3.  **Assembler:** Converts assembly into machine-code object files.
4.  **Linker:** Combines object files and libraries into a final executable.

The tutorial explains that in a standard compilation, the linker silently includes CRT startup files (like `crt1.o`). These files contain the `_start` symbol, which is the actual entry point the Linux kernel jumps to when a program begins. `_start` initializes the standard library (`glibc`) and subsequently calls `main()`.

By using the `-nostartfiles` flag, a developer can bypass these startup files. However, the author notes that doing so breaks standard library functions like `printf()`, because `glibc` is never initialized. To create a functional program without `main()`, the author demonstrates how to:
*   Define a custom C function to provide the program logic.
*   Manually write a `_start` symbol in assembly.
*   Use raw **system calls** (syscalls), specifically `sys_write` for output and `sys_exit` for termination, to communicate directly with the kernel.

Ultimately, the article proves that by providing a manual `_start` and handling kernel-level transitions, one can produce a valid, running ELF binary that operates entirely without a `main()` function or standard library dependencies.
